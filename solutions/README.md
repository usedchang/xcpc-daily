# 题解目录

本目录存放每道题的本地 Markdown 题解与同名标程，**按月份分目录**：

```
solutions/2026-09/
  2026-09-08.md        与题目 date 同名的题解
  2026-09-08.cpp       同名标程（可选，仅作留档，页面不读取）
  2026-09-09.md
  2026-09-09.cpp
solutions/community/   社区投稿（约定见 CONTRIBUTING.md）
```

## 文件名约定

- **目录**：题目 `date` 的月份，即 `solutions/2026-09/`。
- **默认文件名**：与 `data/<年-月>.json` 中该题的 `date` 相同，例如 `2026-09-08.md`。
- **显式指定**：在对应月份 json 的题目里加 `"solution": "2026-09-08-xor-is-add"`（只写文件名，
  目录按 `date` 的月份自动补；`.md` 可省略）。
- **标程**：与题解同名的 `.cpp` 放同一个目录即可（`2026-09-08.cpp`），页面不会读它。
- **旧布局兼容**：直接放在 `solutions/` 根目录下的 `2026-09-08.md` 仍能被找到，方便渐进迁移。
- 以 `_` 开头或名为 `README` 的 `.md` 会被忽略（本文件即如此）。

## 页面怎么读到这些文件

1. **运行时 fetch 优先**：构建会把 `solutions/<年-月>/*.md` 拷进产物目录，
   页面用 `cache: "no-store"` 去取 `./solutions/<年-月>/<文件名>.md`。
   所以改完 md 直接覆盖部署目录里的同名文件即可生效，不必重新构建。
2. **内联兜底**：dev / build 时所有 md 也被 `import.meta.glob` 打进 JS。
   文件不存在、离线、或托管方对未知路径回退返回 `index.html` 时，页面会改用这一份
   （靠响应体嗅探认出整页 HTML，不会把它当题解渲染出来）。
3. **新加的题解**需要重新构建一次：文件名清单是构建期扫描出来的。
   （旧布局 `solutions/2026-09-08.md` 也仍然认，方便渐进迁移。）

## 内容格式

标准 Markdown，支持标题、加粗、行内代码、代码块（带语言名）、列表、表格、引用、图片等。
正文里的相对图片路径按**站点根目录**解析（例如 `![](./2026-09-13.png)` 对应 `public/2026-09-13.png`），
不要写仓库内的相对路径。

## Hint（提示）

Hint 直接写在题目数据（`data/<年-月>.json`）里，与题解正文独立，仅在点击标题时展开，类似 codeforces 的 Hint：

```json
{
  "date": "2026-09-08",
  "source": "…",
  "title": "…",
  "link": "…",
  "hints": [
    "第一个提示：可以按位考虑。",
    "第二个提示：用 `trie` 维护。"
  ]
}
```

每个字符串是一个 hint，按顺序显示为 `Hint 1`、`Hint 2`……，点击标题展开/收起，内容也走 Markdown 渲染。
