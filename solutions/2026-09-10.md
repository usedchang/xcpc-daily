这是一道经典的`根号分治`题目
可以优先考虑暴力怎么做?
先进行前缀和快速求和。
对每个区间都进行一次最大值查询 ,这样的复杂度是 $qk$的，我们无法接受.
再考虑对答案进行记忆化操作,我们可以花费 $O(k \times n^2)$ 的时空轻易的记忆化每一个区间,但是这样的空间复杂度我们又无法接受。

有没有一种算法能结合以上两种算法的优缺点？

有的！！！

把询问 $k$的大小按 $K$ 分类
询问k小于$K$ 时直接暴力计算的时间复杂度不超过 $O(q K)$ 


询问k 大于 $K$ 时, $nk \leq (N=5\times 10^5)$得出 $n \leq \frac{N}{k}$这样的区间我们可以耗费 $O(k n^2)=O(\lceil \frac{N^2}{K} \rceil)$ 的时空复杂度轻易的记忆化。

这样我们总体复杂度取到 $O(qK+ \lceil \frac{N^2}{K} \rceil)$, $q$ 与 $n$ 上界一致,因此可以视为同阶 $O(N(K+\frac{N}{K}))$

根据~~基本不懂式~~基本不等式，当$K= \frac{N}{K}= \sqrt N$ 时复杂度取最小达到 $O(N \sqrt N)$

```cpp
#include<bits/stdc++.h>
using namespace std;
#define endl '\n'
typedef long long ll;
void solve(){
    int n,k,q;
    cin>>n>>k>>q;
    vector<vector<int>>a(k+1,vector<int>(n+1));
    vector<vector<ll>>pre(k+1,vector<ll>(n+1));
    for(int i=1;i<=k;i++){
        for(int j=1;j<=n;j++) cin>>a[i][j],pre[i][j]=pre[i][j-1]+a[i][j];
    }
    const int N=5e5;
    int L=sqrt(N);
    if(k>L){
        vector<vector<ll>>res(n+1,vector<ll>(n+1));
        for(int i=1;i<=k;i++){//k
            for(int len=1;len<=n;len++){//N/k
                for(int l=1;l+len-1<=n;l++) {//N/k
                    int r=l+len-1;
                    res[l][r]=max(res[l][r],pre[i][r]-pre[i][l-1]);
                }
            }
        }
        while(q--){
            int l,r;
            cin>>l>>r;
            cout<<res[l][r]<<endl;
        }
    }
    else{
        while(q--){
            int l,r;
            cin>>l>>r;
            ll ans=0;
            for(int i=1;i<=k;i++) ans=max(ans,pre[i][r]-pre[i][l-1]);
            cout<<ans<<endl;
        }
    }
}
int main(){
    cin.tie(0)->ios::sync_with_stdio(false);
    int T=1;//cin>>T;
    while(T--) solve();
    return 0;
}
```

这题还有一种写法，代码层面比上面简单，但是复杂度平衡分析上略难：
```cpp
#include<bits/stdc++.h>
using namespace std;
#define endl '\n'
typedef long long ll;
struct custom_hash {
    static uint64_t splitmix64(uint64_t x) {
        x += 0x9e3779b97f4a7c15ULL;
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ULL;
        x = (x ^ (x >> 27)) * 0x94d049bb133111ebULL;
        return x ^ (x >> 31);
    }
    size_t operator()(const pair<int,int>& p) const {
        static const uint64_t FIXED_RANDOM = 
            chrono::steady_clock::now().time_since_epoch().count();
        // 将 first 和 second 混合，防止 (1,2) 和 (2,1) 冲突
        return splitmix64(p.first + FIXED_RANDOM) ^ 
               (splitmix64(p.second + FIXED_RANDOM) >> 1);
    }
};
void solve(){
    int n,k,q;
    cin>>n>>k>>q;
    vector< vector<int> >a(k+1,vector<int>(n+1));
    vector< vector<ll> >pre(k+1,vector<ll>(n+1));
    for(int i=1;i<=k;i++){
        for(int j=1;j<=n;j++) cin>>a[i][j],pre[i][j]=a[i][j];
    }
    for(int i=1;i<=k;i++){
        for(int j=1;j<=n;j++) pre[i][j]+=pre[i][j-1];
    }
    unordered_map<pair<int,int>, ll, custom_hash> mp;
    for(int i=1;i<=q;i++){
        int l,r;
        cin>>l>>r;
        ll ans=0;
        if(mp.count({l,r})) {
            cout<<mp[{l,r}]<<endl;
            continue;
        }
        for(int j=1;j<=k;j++){
            ans=max(ans,pre[j][r]-pre[j][l-1]);
        }
        cout<<(mp[{l,r}]=ans)<<endl;
    }
}
int main(){
    cin.tie(0)->ios::sync_with_stdio(false);
    solve();
    return 0;
}
```

## 复杂度分析

记：

- $S=5\times 10^5$
- 询问数 $q\le S$
- 数据范围保证 $n\times k\le S$

对于一次询问：

- 如果区间 $[l,r]$ 之前算过，直接从 `map` 输出，复杂度 $O(\log q)$。
- 如果没算过，就暴力枚举 $k$ 个序列求最大值，复杂度 $O(k)$，然后存进 `map`。

所以真正消耗时间的是“第一次出现的不同区间”。

不同区间总数是：

$$
\frac{n(n+1)}2
$$

因此内层循环总次数最多是：

$$
k\times \min\left(q,\frac{n(n+1)}2\right)
$$

利用 $n\times k\le S,\ q\le S$，可以估计：

- 若 $\frac{n(n+1)}2\le q$，则

$$
k\cdot \frac{n(n+1)}2 \approx \frac{S(n+1)}2
$$

而这时 $n\le \sqrt{2q}\le 1000$，所以最多约：

$$
\frac{5\times10^5\times1001}{2}\approx 2.5\times10^8
$$

- 若 $\frac{n(n+1)}2>q$，则

$$
k\cdot q = q\cdot \frac{S}{n} \le S\sqrt{\frac q2}\approx 2.5\times10^8
$$

所以最坏情况下，内层循环次数大约是 **$2.5\times 10^8$** 次。

## 极限什么时候取到？

极限取在：

$$
n=1000,\quad k=500,\quad q=500000
$$

此时：

$$
n\times k=1000\times500=500000
$$

区间总数：

$$
\frac{1000\times1001}{2}=500500
$$

可以构造 $500000$ 个 **互不相同** 的询问。

因为每个区间都是第一次出现，所以每次询问都要跑 $k=500$ 次，总循环次数为：

$$
500000\times500=250000000
$$

这就是最坏情况的上界。
